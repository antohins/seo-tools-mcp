# Яндекс: Вебмастер + Метрика

Два сервиса на одном OAuth-приложении Яндекса, но токены разные — авторизоваться нужно
дважды (`ywm_oauth_start`/`finish`, `metrika_oauth_start`/`finish`). Вебмастер отвечает на
«что происходит в поиске», Метрика — «что дальше делает пришедший человек».

## Настройка

1. `ywm_hosts` → `host_id` в формате `https:example.com:443`. Это не URL, а именно такой
   идентификатор; в `YWM_HOST_ID` кладётся он.
2. `metrika_counters` → числовой `counterId` в `METRIKA_COUNTER_ID`.

## Вебмастер: что где брать

- `ywm_summary` — быстрый снимок: ИКС, страниц в поиске, исключено, число проблем.
- `ywm_popular` — топ-запросы **хоста** за неделю (до 3000). Фильтра по URL здесь нет.
- `ywm_search_queries` — запросы по **конкретному URL**, окно по умолчанию около двух недель.
- `ywm_recommended_queries` — недобранные запросы по URL. Это **аппроксимация**: в API v4
  нет «рекомендованных», инструмент собирает три категории — показы без кликов, позиции
  на грани топа и запросы с низким CTR. Так и подавать пользователю, не как официальный
  список Яндекса.
- `ywm_queries_history` — суммарная динамика (показы, клики, средние позиции) по датам.
- `ywm_indexing_history` — сколько страниц **в поиске** по датам (окно по умолчанию 30 дней).
- `ywm_sqi_history` — история ИКС (по умолчанию 180 дней). ИКС обновляется редко и рывками:
  ежедневная динамика по нему бессмысленна.
- `ywm_diagnostics`, `ywm_broken_links`, `ywm_important_urls`, `ywm_sitemaps` — техническая
  часть. У выборок (`external_links`, `broken_links`) есть `truncated: true` и `offset` —
  считать «всего» по одной выборке нельзя, для этого есть `count`.

## Метрика: что где брать

- `metrika_traffic_sources` — визиты по каналам (`organic`, `direct`, `ad`, `referral`…).
- `metrika_top_landings` — топ посадочных **из органики**.
- `metrika_landing_behavior` — поведение по конкретной посадочной, с `source: 'organic'`
  и достижениями целей (`goalIds`; список — `metrika_goals`).
- `metrika_search_phrases` — поисковые фразы по посадочной. **В основном Яндекс**: Google
  свои запросы шифрует, поэтому по нему тут почти пусто, и это не поломка.
- `metrika_report` / `metrika_bytime` — произвольные отчёты Stat API, имена вида `ym:s:<name>`.

Два поля в ответах, которые нельзя игнорировать: `sampled: true` — цифры получены по
выборке, точность не абсолютная; `truncated: true` — строки обрезаны лимитом, `totalRows`
показывает реальный размер. `bounceRate` — **процент** (0–100), не доля.

## Связка

Общий ключ между сервисами — **посадочная страница**.

Типовой разбор просадки:

1. `ywm_queries_history` за 90 дней — упали показы или клики.
2. Упали показы → `ywm_indexing_history` и `ywm_diagnostics`: страницы выпали из поиска или
   появились проблемы.
3. Упали клики при живых показах → `ywm_popular` / `ywm_search_queries` по ключевым URL:
   позиции просели или сменились сниппеты.
4. `metrika_top_landings` за те же периоды — какие посадочные потеряли органику.
5. По пострадавшим — `metrika_landing_behavior` с `source: 'organic'`: если отказы выросли
   до просадки, проблема на странице, а не в выдаче.

## Чего не делать

- Не сравнивать абсолютные визиты Метрики с кликами Вебмастера: разные модели счёта, разные
  фильтры ботов, часть кликов не доходит до счётчика. Сравнивать динамику.
- Не искать Google-запросы в `metrika_search_phrases` — для Google есть `gsc_query`.
- Не строить выводы по `ywm_sqi_history` за короткое окно.
- Не выдавать `ywm_recommended_queries` за официальную рекомендацию Яндекса.
