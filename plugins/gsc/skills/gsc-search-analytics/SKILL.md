# Search Console: как читать данные, не обманываясь

## Порядок

1. `gsc_auth_status`. Нет токена — `gsc_oauth_start` → пользователь открывает ссылку →
   `gsc_oauth_finish`. Сервис-аккаунт работает, но его почту надо вручную добавить в каждое
   свойство; OAuth видит все свойства аккаунта сразу.
2. `gsc_list_sites` — какие свойства доступны. Свойства бывают двух видов:
   `sc-domain:example.com` (домен целиком) и `https://example.com/` (URL-префикс, **со слэшем
   на конце**). Это разные свойства с разными данными.
3. Дальше `gsc_query` с нужными `dimensions`.

## Три вещи, из-за которых цифры «не сходятся»

**Свежесть.** Данные отстают на 2–3 дня. `endDate: сегодня` вернёт провал в конце периода,
который выглядит как обвал трафика. Для отчётов брать `endDate` = сегодня минус 3 дня.
`dataState: 'all'` подмешивает свежие неполные данные — годится для «что происходит прямо
сейчас», но не для сравнения периодов.

**Окно.** Глубина — 16 месяцев. Запрос за более ранний период вернёт пустоту, а не ошибку.

**Суммы не сходятся по построению.** Клики по разрезу `query` не дадут общую сумму: запросы
с малым числом показов Google не отдаёт (anonymized queries). Поэтому «сумма по запросам» и
«всего кликов по сайту» — разные числа, и это не баг. Общий итог брать отдельным вызовом без
`dimensions: ['query']`.

## Разрезы

- `dimensions: ['query']` — что спрашивают.
- `['page']` — какие страницы собирают.
- `['query','page']` — связка; на ней ловится каннибализация: один запрос, несколько страниц.
- `['date']` — динамика.
- `['country']`, `['device']` — сегменты.

`position` — усреднённая позиция показа, а не позиция в моменте. Сравнивать её со снятой
через `xmlstock_serp`/`xmlriver_serp` позицией напрямую нельзя: там слепок выдачи по одному
региону и устройству, здесь среднее по всем.

`ctr` возвращается долей (0..1), не процентом.

## Типовые задачи

**Просадка трафика.** `['date']` за 90 дней → найти точку слома. Затем тот же период в
разрезе `['query']` и `['page']` до и после: упало по всем запросам (алгоритм, сезон) или по
конкретной группе (потеря конкретных позиций).

**Недобранные запросы.** `['query','page']`, отфильтровать строки с высокими `impressions`
и позицией 5–20: показы есть, кликов мало — это правки title/description и доработка
страницы, а не новый контент.

**Каннибализация.** `['query','page']` → сгруппировать по `query`, оставить запросы, где
больше одной страницы с заметными показами.

**Почему страницы нет в Google.** `gsc_inspect_url` — `verdict`, `coverageState`,
`robotsTxtState`, канонический URL по мнению Google против заявленного. Расхождение
каноникалов — самая частая причина «страница есть, но её нет в поиске».

**Сайтмапы.** `gsc_list_sitemaps` — ошибки, дата последнего скачивания, число URL по типам.

## Чего не делать

- Не брать `endDate` сегодняшним числом в отчётах о динамике.
- Не выдавать сумму кликов по запросам за общий трафик.
- Не смешивать `searchType: 'web'` с `image`/`video`/`news` в одном выводе.
- Не считать `gsc_query` источником по Яндексу: там только Google. Яндекс — `ywm_*`.
